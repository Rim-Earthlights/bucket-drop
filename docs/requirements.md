# フォルダ → S3 自動アップローダー 要件・受け入れ条件

作成日: 2026-11-04

## 0. 概要

Windows のタスクトレイに常駐するアプリ。指定フォルダ以下のファイルの追加・変更・削除を監視し、Amazon S3 に自動で反映する。

- 用途: スクリーンショットツールが監視フォルダに保存した画像を S3 に上げ、公開 URL で共有する。
- S3 への操作はすべて **AWS SDK** で行う。外部コマンド（AWS CLI など）は使わない。
- 実装言語・フレームワークは自由（Windows で動き、タスクトレイに常駐できること）。
- トレイアイコン用の `.ico` は別途渡す。無ければ仮のアイコンでよい。

凡例: **[必須]** 受け入れに必要 / **[推奨]** 実装する。ただし事情があれば相談 / **[検討]** 実装しなくてよい。設計上の拡張余地だけ残す

---

## 1. 保存ルール

- [ ] **[必須] R-1** 監視ルート直下のフォルダ名を **バケット名** とし、その下の相対パスを **オブジェクトキー** とする。
  - 例: 監視ルートが `D:\share\` のとき `D:\share\my-bucket\2026\11\a.png` → バケット `my-bucket`、キー `2026/11/a.png`
  - 例: `D:\share\my-bucket\a.png` → バケット `my-bucket`、キー `a.png`
- [ ] **[必須] R-2** キーの区切り文字は `/` にする（Windows の `\` を変換する）。
- [ ] **[必須] R-3** 監視ルートの指定は、末尾に `\` があってもなくても同じ結果になる。
- [ ] **[必須] R-4** 監視ルート直下に置かれたファイル（バケットフォルダに入っていないもの）はアップロードしない。その旨を警告として通知し、ログにも残す。
- [ ] **[必須] R-5** 日本語・空白・記号を含むファイル名も、名前を変えずにそのままキーにする。
- [ ] **[必須] R-6** 対象は **拡張子のあるファイルだけ**（ファイル名が `.英数字` で終わるもの）。拡張子の無いファイルとフォルダ自体は、ファイルイベントの対象にしない（フォルダ操作の扱いは X-7 を参照）。

## 2. フォルダ監視

- [ ] **[必須] W-1** 監視ルート以下をサブフォルダも含めて監視する。
- [ ] **[必須] W-2** ローカルの操作と S3 の操作を次のように対応させる。

  | ローカルの操作 | S3 の操作 |
  |---|---|
  | ファイル作成 | PutObject |
  | ファイル変更 | PutObject（上書き） |
  | ファイル削除 | DeleteObject |
  | リネーム・監視ルート内での移動 | 旧キーを DeleteObject → 新キーへ PutObject |

  - 移動先や移動元が R-4 や R-6 の対象外なら、その側の操作は行わない。
  - 移動元と移動先のバケットが違ってもよい。
- [ ] **[必須] W-3** 1回の保存で連続して起きるイベント（作成 → 変更 ×n など）は一定時間まとめて扱い、**アップロードは1回**にする（デバウンス。目安 500ms〜1s、設定で変更できるとよい）。
- [ ] **[必須] W-4** **ファイルの書き込みが終わってから**アップロードする。排他オープンできるか、サイズが一定時間変わらないかで判定する。書き込み途中のファイルは上げない。
- [ ] **[必須] W-5** 監視の一時停止と再開ができる。停止中のイベントは処理しない。

## 3. S3 操作

- [ ] **[必須] S-1** AWS SDK で PutObject / DeleteObject を実行する。外部プロセスは起動しない。
- [ ] **[必須] S-2** **`Content-Type` を拡張子から判定して設定する**（例: `.png` → `image/png`、`.jpg` → `image/jpeg`、`.gif` → `image/gif`、`.webp` → `image/webp`、`.mp4` → `video/mp4`。判定できなければ `application/octet-stream`）。
  - これが無いと、公開 URL をブラウザで開いたときに画像が表示されずダウンロードになる。
- [ ] **[必須] S-3** 大きいファイル（目安 16MB 以上）はマルチパートアップロードにする。SDK の高レベル転送 API を使ってよい。
- [ ] **[必須] S-4** 成功か失敗かは API の結果で判定する。失敗したときに成功の通知を出さない。
- [ ] **[必須] S-5** バケットごとにリージョンが違っても動く。GetBucketLocation などでリージョンを解決し、結果をキャッシュする。
- [ ] **[必須] S-6** オブジェクト ACL は付けない（公開設定は 4章のとおりバケット側で行う）。
- [ ] **[推奨] S-7** 一時的な失敗（ネットワーク断、5xx、スロットリング）は指数バックオフで再試行する（目安: 最大 5 回）。最終的に失敗したら通知する。

## 4. 公開設定（アプリ外の前提）

- バケットは「ACL 無効（オブジェクト所有者の強制）」とし、バケットポリシーで `s3:GetObject` を `Principal: *` に許可して公開する。これはアプリの責務ではなく、セットアップ手順として README に書く。
- [ ] **[必須] P-1** 上の設定をしたバケットで、アップロードしたオブジェクトに `https://<bucket>.s3.<region>.amazonaws.com/<key>` で認証なしにアクセスでき、ブラウザで画像が表示される。
- [ ] **[検討] P-2** CloudFront や独自ドメイン経由の URL に対応する（X-8 の URL のベースを設定で変えられれば足りる）。

## 5. 認証・権限

- [ ] **[必須] A-1** 認証情報は **SDK 標準の認証チェーン**（`~/.aws/credentials` のプロファイル、SSO、環境変数）から取得する。アプリの設定ファイルにアクセスキーを保存しない。
- [ ] **[必須] A-2** 使うプロファイル名を設定で指定できる（未指定なら default）。
- [ ] **[必須] A-3** 認証できないときは、起動時か初回操作時にわかるエラーを通知する。
- [ ] **[推奨] A-4** 必要な IAM 権限を README に書く。対象バケットへの `s3:PutObject` / `s3:DeleteObject` / `s3:GetBucketLocation`、X-4 を実装するなら `s3:ListBucket` も。最小権限のポリシー例を載せる。

## 6. 常駐 UI

- [ ] **[必須] U-1** 起動するとタスクトレイに常駐する。メインウィンドウは出さず、タスクバーにも出さない。
- [ ] **[必須] U-2** トレイの右クリックメニューに「監視の一時停止/再開」と「終了」がある。今の状態が分かる（チェック表示やラベルの切り替えで）。
- [ ] **[必須] U-3** 次のタイミングで Windows のトースト（バルーン）通知を出す: アップロード完了（ファイル名）、削除完了（ファイル名）、失敗（ファイル名と理由の要約）、監視の開始と停止。
- [ ] **[必須] U-4** 二重起動を防ぐ。2つ目は既に起動中である旨を知らせて終了する。
- [ ] **[必須] U-5** アップロード中も UI が固まらない。S3 の処理は非同期のキューで行う。同じキーへの操作は、起きた順に処理されることを保証する。
- [ ] **[推奨] U-6** 完了時の効果音を設定でオン/オフできる（既定はオン）。

## 7. 設定

- [ ] **[必須] C-1** 設定項目: 監視ルートのパス、AWS プロファイル名。ほかの章で「設定で」と書いた項目もここに含める。
- [ ] **[必須] C-2** 設定ファイルは `%APPDATA%\<アプリ名>\` に JSON か TOML で置く。
- [ ] **[必須] C-3** 設定ファイルが無いときはひな形を作り、その場所を知らせて終了する。監視パスが存在しないときは、エラーを通知して終了する。
- [ ] **[推奨] C-4** トレイメニューから設定ファイル（またはそのフォルダ）を開ける。

## 8. 追加要件

### 8.1 安全性
- [ ] **[推奨] X-1** README に、誤削除への備えとして **S3 バケットのバージョニングを有効にし、古いバージョンをライフサイクルルールで N 日後に消す** 手順を書く。ローカルで削除すると S3 からもすぐ消えるため。
- [ ] **[推奨] X-2** 削除を S3 に反映するかを設定で切り替えられる（既定は反映する）。
- [ ] **[推奨] X-3** 除外パターンを設定で指定でき、既定で `*.tmp`, `~$*`, `Thumbs.db`, `desktop.ini`, 隠しファイルを除外する。

### 8.2 取りこぼし対策
- [ ] **[推奨] X-4 起動時の差分同期**: 起動時と、トレイメニューから手動で実行したときに、監視ルート以下のファイルと S3 の一覧（ListObjectsV2）を比べ、S3 に無いもの・サイズが違うもの・ローカルの方が新しいものをアップロードする。
  - この同期では **S3 側の削除は行わない**。
- [ ] **[推奨] X-5** ファイル監視のイベントを取りこぼした（監視 API がバッファあふれなどのエラーを出した）ときは、X-4 と同じ再スキャンで復旧する。
- [ ] **[検討] X-6** 処理待ちのキューをディスクに保存し、オフライン中や強制終了でも作業が失われないようにする。

### 8.3 フォルダ単位の操作
- [ ] **[検討] X-7** フォルダの削除とリネームを扱う。必須にしない場合は、フォルダ操作をしても S3 側は変わらないこと（中のファイルが残ること）を README に書く。
  - 実装するなら、削除されたフォルダのプレフィックス配下を削除する。リネームされたら、新しいプレフィックスにコピーしてから旧プレフィックスを削除する。

### 8.4 使い勝手
- [ ] **[推奨] X-8 公開 URL をクリップボードにコピーする**: アップロードが成功したら、そのオブジェクトの公開 URL をクリップボードにコピーする。設定でオン/オフでき、URL のベースも変えられる（既定は P-1 の形式。CloudFront 用に `https://cdn.example.com/{bucket}/{key}` のようなテンプレートを指定できる）。
- [ ] **[推奨] X-9** ログをファイルに出す（日時、操作、バケット、キー、結果、エラー内容）。ローテーションする。トレイメニューからログフォルダを開ける。
- [ ] **[検討] X-10** Windows ログイン時に自動で起動するかを設定で切り替えられる。

---

## 9. やらないこと

- AWS CLI など外部コマンドの起動
- オブジェクト ACL の付与
- S3 → ローカル方向の同期（ダウンロード）
- 設定ファイルへの AWS アクセスキーの保存
- データベースなど外部ストアの利用

## 10. 受け入れテスト

監視ルートを `<ROOT>`、テスト用バケットを `<B>` とする（`<ROOT>\<B>\` のフォルダを作っておく）。特に書いていない限り、各テストのあとで S3 の状態と通知を確認する。

| # | 操作 | 期待結果 | 関連 |
|---|---|---|---|
| T-1 | `<ROOT>\<B>\a.png` を置く | `s3://<B>/a.png` ができ、`Content-Type: image/png`、公開 URL をブラウザで開くと画像が表示される。完了通知が1回だけ出る | R-1, S-2, P-1, W-3 |
| T-2 | `<ROOT>\<B>\2026\11\日本語 ファイル.jpg` を置く | `s3://<B>/2026/11/日本語 ファイル.jpg` ができる | R-1, R-2, R-5 |
| T-3 | 監視ルートを末尾 `\` あり・なしで設定し、それぞれ T-1 を行う | どちらも同じ結果になる | R-3 |
| T-4 | `<ROOT>\x.png` を置く | アップロードされない。警告の通知とログが出る | R-4 |
| T-5 | `<ROOT>\<B>\noext` を置く | 何も起きない | R-6 |
| T-6 | T-1 のファイルを上書き保存する | オブジェクトが更新される（ETag が変わる） | W-2 |
| T-7 | T-1 のファイルを削除する | `s3://<B>/a.png` が消える | W-2 |
| T-8 | `<ROOT>\<B>\b.png` を `c.png` にリネームする | `b.png` が消え、`c.png` ができる | W-2 |
| T-9 | 書き込みに数秒かかる大きいファイル（100MB 程度）をコピーで置く | コピー完了後に1回だけアップロードされ、サイズが一致する。アップロード中もトレイメニューが反応する | W-4, S-3, U-5 |
| T-10 | 監視を一時停止してからファイルを置き、再開する | 停止中のファイルは上がらない（X-4 を実装した場合は、手動同期で上がる） | W-5, X-4 |
| T-11 | ネットワークを切ってからファイルを置く | 再試行したあと、失敗の通知が出る。成功の通知は出ない | S-4, S-7 |
| T-12 | 存在しないプロファイル名を設定して起動する | 認証エラーが通知される | A-2, A-3 |
| T-13 | アプリを2つ起動する | 2つ目は起動中である旨を知らせて終了する | U-4 |
| T-14 | 別リージョンのバケット `<B2>` で T-1 を行う | 正常にアップロードされる | S-5 |
| T-15 | 設定ファイルを消して起動する | ひな形ができ、場所が通知され、アプリは終了する | C-3 |
| T-16 | X-8 を有効にして T-1 を行う | クリップボードに公開 URL が入っている | X-8 |
